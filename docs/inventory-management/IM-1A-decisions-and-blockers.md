# IM-1A 결정 및 차단 항목

## 사용자 결정 필요

1. 멀티테넌트 membership 모델과 복수 학교 소속 허용 여부
2. 강사의 공용 사용이력 열람 범위와 보존기간
3. 기본/포장 단위, 분수 수량 및 scale 정책
4. 만료일 당일 사용 가능 여부(잠정: 가능)
5. 권위 원본과 전환 기준시각
6. 혼합형 스키마 전략 승인
7. 기존 UUID 재사용 대 mapping table 선택
8. 초과입고 허용 및 승인 방식

## 추가 확인 필요

- 코드 project ref의 Supabase 접근 권한과 dev/QA/prod 구분
- 실제 DB에 migration/RLS/RPC가 적용됐는지
- 자동 백업/PITR/보존기간/복원 담당자
- 운영자가 실제로 갱신하는 재고 시스템
- 실제 품목에 분수 단위가 필요한지(운영 데이터 전체 열람 없이 업무 확인)

## 위험

- 기존 authenticated 직접 DML을 남기면 RPC와 movement 원장을 우회할 수 있다.
- 기존 lot 수량은 잔량이 아니라 입고량 성격이며 만료 재고도 합계에 포함한다.
- 기존 멱등성은 payload 충돌을 식별하지 않는다.
- NEIS 학교정보는 사용자가 수정 가능한 개인 설정이어서 tenant 권위가 될 수 없다.
- `profiles.role`은 전역 공지 관리자 역할이며 학교별 inventory 역할로 재사용하면 안 된다.
- 운영/개발 프로젝트가 분리되지 않았다면 migration 및 QA 위험이 높다.

## 판정

`CONDITIONAL`. 계약 초안과 코드 근거는 확보했지만 실제 운영 DB/백업 및 권위 원본이 확인되지 않았고 주요 업무 결정이 남았다. IM-1B는 자동 착수하지 않는다.
