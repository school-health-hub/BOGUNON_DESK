# IM-0 마이그레이션·롤백 계획

## 원본 우선순위

Google Sheets는 초기 업무 규칙과 과거 구조의 참고자료다. 현재 운영 재고의 권위는 BOGUNON 운영 DB와 담당자 대조 후 결정한다. 이번 조사에서는 실제 운영 DB를 조회하지 않았으므로 확정하지 않았다.

## 단계

1. 세 원본의 변경 중단 시점과 책임자를 확정한다.
2. 암호화 백업과 SHA-256 목록을 만든다. 개인정보/비밀은 설계 문서에 넣지 않는다.
3. 품목 정규화 후보를 만들되 자동 병합하지 않는다.
4. legacy row → itemId/lotId 매핑을 승인받는다.
5. 규격, 기본/포장 단위와 변환계수를 검증한다.
6. 유효기간별 로트를 만들고, 이력이 없는 현재고는 `INITIAL_BALANCE` movement로 기준일·출처를 기록한다.
7. Google Sheets 입고기록과 BOGUNON receipts가 같은 입고인지 중복 검증한다.
8. 합성 데이터로 반복 가능한 dry-run을 수행한다.
9. 실제 이전 전 승인, write freeze, 최종 export를 수행한다.
10. 이전 후 품목 수, 로트 수, 총/가용 수량, 만료·격리량, 구매 연결을 대조한다.
11. 제한된 사용자로 병행 조회 후 신규 쓰기를 연다.

과거 사용·입고 이력을 근거 없이 생성하지 않는다. 품명 괄호 번호는 로트 힌트일 뿐 itemId로 사용하지 않는다.

## 롤백

- cutover 전: 신규 데이터셋 폐기 후 원본 계속 사용.
- cutover 후 제한 기간: 신규 쓰기 중단, movement 이후 변화량 export, 원본 복원 여부를 승인 후 결정.
- dual-write는 복잡성과 중복 위험 때문에 기본 금지. 필요하면 단방향 이벤트와 재처리 키를 별도 설계한다.
- 롤백 리허설은 합성 데이터에서 백업 복원, 수량·ID·감사 연결을 검증해야 한다.
