- 파일 수정 시각만으로 현재 운영 최신본임을 입증할 수 없다. 운영 담당자의 최신본 확인이 필요하다.
- Excel 변환본에는 Google Sheets 함수 손상 흔적이 있다. 계산 결과를 운영 진실로 간주하면 안 된다.

## 시트 구조

| 시트 | 구조와 역할 | 확인 결과 |
|---|---|---|
| `메인재고대장` | 7행 헤더, A:K 기본 데이터, L:N 구매 입력 | 현재고는 직접 입력값. 잔여일수·안전·재고상태만 수식 |
| `구매계획` | 구매선택 품목 자동 목록 | Google `FILTER`가 `__xludf.DUMMYFUNCTION`과 캐시값으로 변환되어 Excel 호환 손상 |
| `품의참고자료` | 예산·품의 표 | `FILTER` 변환 손상, 구매계획 합계 참조 |
| `대시보드` | 월별 입고 건수·지출·예산 | `SUMIFS`, `COUNTIFS`, `EOMONTH`; 존재하지 않는 `근무기록` 참조 1건 확인 |
| `입고기록` | 입고일·품명·수량·단가·합계·반영완료 | 합계는 수량×단가. 메인 현재고로 반영하는 수식/트랜잭션은 없음 |

## 실제 열과 계산

`메인재고대장`: 분류, 품명, 규격/단위, 현재고, 권장재고, 유통기한, 잔여일수, 안전상태, 재고상태, 비고, 관리TIP, 구매선택, 구매수량, 예상단가.

- 잔여일수: `유통기한 - TODAY()`.
- 안전상태: 음수면 즉시폐기, 90일 이하면 교체준비, 그 외 정상.
- 재고상태: 현재고가 권장재고보다 작으면 부족, 아니면 충분.
- 대시보드 경고 수: 상태 텍스트에 대한 `COUNTIF`.
- 예상 구매금액: 구매수량×예상단가.
- 실제 지출: 입고기록의 월별 합계를 `SUMIFS`로 집계.

## 로트와 이력

- 동일 품목의 유효기간별 행 분리는 품명 뒤 괄호 번호를 붙이는 관행에 의존한다.
- 고유 품목 ID, 로트 ID, 요청 ID가 없다.
- 입고기록은 존재하지만 현재고와 원자적으로 연결되지 않는다.
- 사용·폐기·정정 이력은 없다.
- `반영완료` 체크박스가 있으나 데이터베이스 수준 중복 방지 장치가 아니다.

## 유효성·서식

- 분류와 관리TIP에 목록 유효성 검사가 있다.
- 안전상태·재고상태 조건부서식이 있다.
- 구매선택과 구매완료/반영완료는 체크박스형 불리언 값으로 저장된다.
- 수식 범위와 데이터 범위가 서로 다르고, 일부 시트는 1,000행 수준의 서식/수식을 가진다.

## 판정

- 업무 규칙 참고자료: 재사용 가능.
- 현재고 원본: 최신성 및 메인-입고 정합성 확인 전에는 확정 불가.
- Google Sheets 자동 구매계획: Excel 변환본에서는 신뢰 불가.
- 신규 시스템에는 ID, 로트, 이동원장, 원자적 차감, 감사와 멱등성이 새로 필요하다.
