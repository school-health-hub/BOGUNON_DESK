# IM-0 UI 워크플로

## DESK 관리자

기존 `workspace-shell`, dock/action registry, modal/detail panel, 디자인 토큰을 재사용한다. Inventory를 대시보드 위젯 하나에 모두 넣지 않고 독립 workspace/panel로 연다. 좁은 창에서는 1열, 일반 데스크톱에서는 목록+상세 2열을 사용한다.

1. 재고 대시보드: 전체 품목, 부족, 임박, 만료, 최근 사용, 입고 대기.
2. 전체 물품: 검색·분류·상태 필터, 가용/총재고 구분.
3. 물품 상세: 기본정보, 로트, 이동원장, 구매 연결.
4. 입고 관리: Purchase Helper 연결 건, 부분입고, 로트/기한 확인 후 확정.
5. 사용 이력: 행위자·시각·로트 배분·취소 연결.
6. 유효기간: FEFO 순, 격리/만료/폐기 상태.
7. 부족/구매 후보: 목표 대비 부족량, 후보 생성/전달.
8. 폐기·정정: 사유 필수, 영향 미리보기와 재확인.
9. 감사 기록: 필터·원본 요청 ID·전후 값.
10. 설정: 단위/임박 기준/구성원. 위험 설정은 별도 권한.

상태는 loading/empty/error/offline/stale/permission denied/conflict를 모두 설계한다. 재고 변경 성공은 서버 movement ID를 받은 뒤에만 표시한다.

## 강사 웹

- 홈: 큰 검색 입력, 최근 사용, 부족/기한 안내. 관리자 통계는 노출하지 않는다.
- 상세: 품명, 규격, 가용재고, 가장 가까운 사용 가능 기한, 보관 위치(필드 확정 시).
- 사용 기록: 품목 선택 → 수량 입력 → 확인 → 서버 처리 결과. 최근 수량 버튼은 보조 수단으로만 제공.
- 이력: 허용된 범위의 날짜·품명·수량·상태.

## 장애 UX

- 중복 클릭: 첫 클릭 때 생성한 requestId를 유지하고 버튼 잠금. 재시도도 같은 ID 사용.
- 네트워크 오류: “성공 여부 확인 중”으로 두고 requestId 조회 후 재전송.
- 세션 만료: 입력을 비민감 임시 상태로 유지하되 확정하지 않고 재로그인.
- 재고 부족/경합: 서버 결과와 최신 가용재고를 표시하고 수량 재입력.
- 오프라인: 조회 캐시 시각을 표시하고 사용 확정 버튼 비활성화.
