# POPUP-UX-IMPLEMENT-01 — 원고 종료 보호와 업데이트 확인

제품 기준 SHA `242b03e3aa14f1c496dad9ea30b46e77d0a28608`, 감사 기준 `b4e43d6e83686269c5efb6c21e9bf9d0b1288728`. 운영 설치본, 운영 프로필, GitHub Release는 검증에 사용하지 않았다.

## P0 근거와 수정

기준 main의 트레이 완전 종료와 일반 종료 분기는 Newsletter의 `closeRequest`를 거치지 않고 flush와 종료를 시작한다. 기존 flush가 React 안에 있는 편집 내용을 저장하는 경로는 없다는 것을 코드에서 확인했다. 기준 빌드의 Windows 시도는 CDP 시작 타임아웃으로 미저장 상태에서 종료하는 실제 전/후 재현을 완료하지 못했다. 아래의 수정 후 Windows 시험은 합성 미저장 원고를 사용했다.

- 트레이와 일반 앱 종료가 Newsletter의 기존 확인 UI에 응답을 요청한다. 요청마다 owner/프레임/URL과 일회성 ID를 검증한다. 대기 중에는 정리·종료를 시작하지 않으며 Electron `before-quit`에서 종료를 막는다. 이미 제출한 응답과 중복 종료 요청은 재사용하지 않는다.
- 현재 원고의 기존 저장 성공 결과를 사용한다. 취소나 실패는 같은 창에 오류를 남기고 종료하지 않는다. 다른 미저장 임시 원고가 있으면 일괄 저장으로 취급하지 않고 개별 저장을 안내한다.
- Windows 세션 종료 요청은 이 작업에서 별도 재현하지 못했고 제품 경로를 변경하지 않았다.

## 업데이트 확인

기존 Windows 메시지 박스의 최종 동의를 Soft Rose 업데이트 창으로 옮겼다. 이전 형태의 제목과 확인/취소 계약은 감사 문서의 `main.mts:171` 및 격리 합성 실행 기록에 있다. 네이티브 이전 화면 캡처는 미확보다.

- ‘계속 작업’을 기본 포커스로 두고 Escape와 승인 전 창 닫기는 취소한다. ‘저장 완료, 설치’를 직접 눌러야 승인할 수 있다. 승인 후에는 Newsletter 보호를 먼저 확인한다. 업데이트 창이 닫히면 보호 단계를 통과하더라도 설치를 시작하지 않는다.
- `UpdateService`의 서명, 크기, SHA-256, 설정된 게시자 검증과 동의 전후 재검증, 설치 도우미·종료 순서는 유지했다. 다운로드 취소는 다운로드 요청이 대기 중이어도 동작하도록 분리했다.
- 기존 업데이트 스타일을 재사용하고 Pretendard를 적용했다. 360px 캡처에서 두 버튼과 한글 문구가 잘리지 않았고 안전 버튼 포커스를 확인했다.
