# Education Video Finder native Phase 1

Native files are isolated at `app_local_data_dir()/education-video/library.json` (on Windows, the app identifier under LocalAppData). No other feature store is read or written. The store contains strict version 1 `{version, items}` JSON. Each item only allows videoId/title/channelId/channelTitle/durationSeconds/url/source/educationTitle/target/schedule/instructions/message/notes. Source is `mock` in Phase 1. Unknown properties (including credential fields), unsupported versions, duplicate IDs, invalid exact YouTube watch URLs, more than 1000 items, and JSON larger than 2 MiB are rejected. The application never stores authentication tokens or API keys here. Teacher free text is stored as entered; do not paste secrets into notes.

Commands: `education_video_library_load`, `education_video_library_save({item})`, `education_video_library_import({json})`, `education_video_library_export`, `education_video_library_recover`. All except export return `{library, recovered}`. Export returns JSON text, for the UI to download. Save is an explicit teacher update and replaces the item for that ID. Import merges IDs and preserves pre-existing teacher notes and edited message. Missing fields are not fabricated.

Every command holds a process-wide mutex across read/merge/write. JSON is validated before mutation. `atomic-write-file` writes a same-directory temporary file and atomically replaces the destination on commit (Windows supported). Before updating an existing primary, its validated content is atomically saved to `library.backup.json`; backup-write failure prevents primary modification. The first successful save creates a backup of its own validated payload before the primary commit. A primary write failure leaves its prior data intact. On subsequent saves, the backup represents the previous valid generation, not an additional cloud copy.

Load detects damaged JSON and automatically recovers a valid backup. The damaged primary is copied byte-for-byte to `library.corrupt.json` first (subsequent quarantines use UUID filenames), including invalid UTF-8/oversized input. If either quarantine or atomic restore fails, an error is shown and no successful recovery is claimed. Missing primary with valid backup also recovers. A missing primary without backup starts empty. If primary and backup are corrupt, neither is overwritten. Explicit recover restores the previous generation and archives the current primary. Import validation failure leaves files untouched. Native tests use temporary directories; browser QA fallback is not evidence of native persistence.

## Finder-only development proxy policy

`BOGUNON_EDUCATION_VIDEO_DEV_PROXY` is a Rust process environment variable. Leave unset for the approved production origin `https://bogunon.vercel.app`. Only debug builds honor the exact values `http://localhost:3000` or `http://127.0.0.1:3000`. Other values are rejected. Release builds ignore this setting and always use the approved HTTPS origin. Credentials, arbitrary hosts/ports, paths, fragments and IPv6 forms cannot pass the exact allowlist. The fixed Finder route is `/api/education-video/search`. Existing meal/weather URL restrictions are unchanged. Phase 1 does not execute HTTP calls; the destination helper prepares the next phase only.

For future local integration, set this variable explicitly in the shell launching the debug Tauri process after the local proxy is available. Do not change the production endpoint or use a user-entered arbitrary URL. Desktop Supabase authentication remains separately configured by `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`; their values are never written to the library.
