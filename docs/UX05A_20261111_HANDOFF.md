# BOGUNON DESK 2.0 — UX-05A 인계

## 기준 및 현재 상태

- 브랜치: `codex/electron-h6-design-renewal`
- Baseline SHA: `378ff55d9f6ffcdcad2f606aa78974a93593cacc`
- 현재 상태: UX-05A 구현과 집중 검증 완료, 최종 커밋 전
- 범위: 공문작업실 한 모듈의 App Shell Workspace 파일럿
- UX-05B, UX-05C, UX-05D 및 Desktop Mode 구현: **NOT STARTED**

## 구현 내용

- 공문작업실을 별도 대형 Workspace overlay 대신 UX-03 App Shell의 Main Workspace outlet에서 표시한다.
- 기존 `P0App.officialDocumentOpen`을 단일 수명주기 owner로 유지한다.
- 기존 `OfficialDocumentWorkspace`의 입력, 미리보기, AI 확인, ODT 저장 및 폐기 확인 계약을 재사용한다.
- Rail에서 다른 카테고리를 선택하면 기존 공문 폐기 확인을 호출한다.
  - 취소: 공문 화면과 임시 원고를 유지한다.
  - 승인: 공문을 닫고 사용자가 선택한 카테고리로 이동한다.
- 공문 내부의 뒤로 가기는 `문서·교육자료` 목록으로 돌아간다.
- Home은 기존 지속 마운트 계약을 유지하며 공문 Workspace 뒤에 노출되지 않는다.

## 실제 Windows 화면 증거

격리된 합성 QA 프로필의 실제 Electron `BrowserWindow.webContents.capturePage()`로 다음 세 화면을 확인했다.

- 1440×835 공문작업실
- 1200×800 공문작업실
- 900×680 공문작업실

세 크기 모두 다음 조건을 통과했다.

- App Rail과 `문서·교육자료 / 공문작업실` 현재 위치 표시
- 공문 입력·미리보기 Workspace 표시
- 문서 전체 가로 넘침 0건
- 화면 밖으로 잘린 공문 작업 버튼 0건
- Renderer 오류 0건
- QA 종료 후 대상 Electron 잔여 프로세스 0건

PNG와 실행 보고서는 Git에 포함하지 않은 로컬 QA 증거로 보존했다. 실제 사용자 정보, 운영 계정 및 운영 DB는 사용하지 않았다.
