# 공문 참고자료 로컬 패키지 v1

Phase 1B는 기존 공문작업실 안에서 검토된 JSON을 수동 반입한다. XLSX 직접 반입, 실시간 Google 연결, 자동 배포, 결제 및 발행자 서명 검증은 지원하지 않는다. 실제 자료를 저장소나 일반 설치본에 포함하지 않는다.

## 패키지 계약

최상위 필드는 `schemaVersion: 1`, `packageId`, `packageVersion`, `publishedAt`, `source`, `usageTerms`, `redistribution`, `review`, `headers`, `rows`다. `review`에는 `reviewer`, `reviewedAt`, `approvedRows`가 필요하며 승인 항목은 `{ sourceNo, sha256 }`다. 날짜는 ISO 형식을 사용한다. 출처와 검토자 표시는 발행자 서명이나 권한 증명이 아니다.

`headers`는 아래 29개 이름을 정확히 한 번씩 포함한다. 순서는 바꿀 수 있으나 추가·누락·중복 열은 허용하지 않는다. 각 `rows` 항목은 헤더에 대응하는 문자열 배열이다.

```text
No, 사용여부, 문서목적, 업무분야, 자료명, 설명, 참고문서URL, 문서ID, 파일형태,
템플릿본문, 붙임예시, 메신저예시, 체크리스트, 공개구분, 비식별여부, 자동본문추출,
상태, 우선순위, 열기, 메모, 자료형태구분, 비식별원문URL, 원문노출여부, 표복사용본문,
표복사안내, AI정리상태, AI정리일시, AI검토필요, AI정리메모
```

승인 해시는 정규화 후 위 순서로 재배열한 29개 셀 배열의 `JSON.stringify` UTF-8 바이트에 대한 SHA-256 소문자 hex다. 줄바꿈은 LF로 통일하고 셀 경계 공백을 제거한다. 내부 탭과 줄 구조는 유지한다. 제작자는 구현의 `hashReferencePackageRow` 함수를 기준으로 해시를 계산한다. 해시는 내용 변경 탐지이며 발행자 인증이 아니다.

입력 한도는 UTF-8 JSON 5 MiB, 데이터 500행, 셀당 50,000자다. 중복 No나 잘못된 구조는 전체 반입을 거부한다. 비활성, 비식별 미확인, 미승인, 해시 불일치 및 개인정보·학교 식별정보 의심 행은 사용 대상에서 제외한다. 검사는 모든 개인정보 탐지를 보장하지 않으므로 배포 전 사람의 검토가 필요하다.

## 사용과 보존

파일 선택 후 검증 결과를 확인하고 반입을 확정한다. 실패·취소는 기존 참고자료와 작성 중 공문을 변경하지 않는다. 전체 교체·삭제도 이미 적용된 공문의 참고자료 스냅샷이나 사용자가 편집한 입력을 자동 변경하지 않는다.

- **이번 실행에서만 사용:** 검증된 자료를 앱 프로세스 메모리에 유지한다.
- **이 PC에 저장:** 제외된 행을 제거한 패키지만 앱의 LocalAppData 아래 `official-document-references/package.json`에 무결성 봉투와 함께 저장한다. 기존 정상 파일을 원자적으로 교체한다. 다음 앱 시작 시 해당 전용 파일만 읽어 무결성과 패키지 검증을 다시 수행한다. 실패한 저장본은 사용하지 않고 공문작업실에서 오류를 안내한다.

원본 파일은 수정하지 않는다. 인증 세션, 금융 DB, 계정 설정, Supabase, 클라우드 동기화 및 앱 백업 경로와 연결하지 않는다. OS 또는 사용자가 별도로 수행하는 파일 백업을 앱이 통제하지는 않는다. 로컬 파일은 콘텐츠 암호화나 DRM을 제공하지 않으며 유료 자료의 복제 방지를 보장하지 않는다.

화면에는 출처·버전·검토 정보·이용 범위·재배포 제한을 일반 텍스트로 표시한다. 반입·복원·검색·선택은 외부 전송을 하지 않는다. 관리용 메모·URL·승인 이력은 기존 AI 프롬프트에 자동 포함하지 않는다. 명시적 AI 사용 시 기존 전송 확인 및 개인정보 점검을 유지한다.

## 검증 경계

자동 테스트는 합성 fixture와 가짜 저장 어댑터만 사용한다. Windows 저장 명령의 실제 파일 교체, 앱 시작, WebView2 파일 선택 및 클립보드는 격리된 Native QA 승인이 있어야 검증할 수 있다. 이번 구현 단계의 TypeScript·단위 테스트 통과를 Native QA 통과로 해석하지 않는다.

## 학교 PC 인계 체크포인트 (2026-10-22)

- Phase 1B 구현은 완료했으며 최종 QA 판정은 **PARTIAL**이다. 이 WIP 체크포인트는 QA 완료나 배포 승인이 아니다.
- 기존 검증 결과: 전체 Vitest 189개 파일·1,255개 테스트 PASS, TypeScript PASS. 이번 체크포인트 작업에서는 테스트나 빌드를 다시 실행하지 않았다.
- 새 Rust 저장 모듈의 컴파일은 시스템 커밋 메모리 보호 조건으로 중단되어 미완료다. Windows 네이티브 앱 실기 QA도 미완료이며, 기존 v0.2.2 설치본에는 Phase 1B가 반영되지 않았다.
- 학교 PC에서는 먼저 브랜치·HEAD·미커밋 작업을 확인하고, 충분한 디스크·커밋 메모리와 해당 PC의 도구 환경을 점검한다. 집 PC 전용 target·임시 경로·로그는 인계 파일에 포함하지 않는다.
- 후속 검증은 승인된 환경에서 `cargo check --locked --offline --jobs 1`, Rust 저장 명령과 TypeScript invoke 계약, 실제 Windows 저장·교체·삭제를 확인한다. 오프라인 의존성이 없으면 임의 다운로드하지 않는다.
- 앱 실행은 운영 프로필·인증·금융 DB·딥링크·외부 통신을 보호하는 격리 환경과 별도 실행 승인 이후에만 수행한다. 합성 JSON 및 PDF·HWPX·ODT로 작성·복사·가져오기와 재시작 복원을 검증한다.
- 실제 Google Sheets·Drive·Apps Script 연결은 계속 HOLD한다. 실제 AI·Supabase 요청, 운영 자료 사용, PR·main 병합·Release·배포는 이 체크포인트의 승인 범위에 포함되지 않는다.
