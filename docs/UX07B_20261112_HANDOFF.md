## 창 수명 계약

- 앱은 기존 단일 Workspace `BrowserWindow`와 renderer를 유지한다.
- 트레이가 준비된 상태에서 창 닫기는 renderer의 기존 모듈 이탈 가드가 승인한 뒤 BrowserWindow 파괴가 아니라 `hide()`다.
- `Workspace 열기`는 기존 창이 최소화됐으면 복원하고, 숨겨졌으면 표시한 뒤 포커스한다.
- 반복 열기와 second-instance 요청은 같은 창을 재사용한다.
- `BOGUNON 완전 종료`와 `before-quit`만 기존 서비스 dispose/flush 및 `app.quit()` 경로를 사용한다.
- 종료가 시작된 뒤에는 열기·숨기기 요청이 창을 되살리지 않는다.
- 트레이 생성에 실패하면 숨겨 접근할 수 없는 상태를 만들지 않고 기존 완전 종료 fallback을 사용한다.
- UX-07C 팔레트가 아직 없으므로 `ready-to-show`의 Workspace 자동 표시는 유지한다.

## 트레이와 재진입

- 트레이·애플리케이션 메뉴: `Workspace 열기`, `Workspace 숨기기`, `BOGUNON 완전 종료`.
- 트레이 더블클릭과 second-instance는 동일한 `open()` 경로를 호출한다.
- 실제 Windows QA에서는 OS 트레이 직접 클릭 대신 real second-instance 경로로 최소화·숨김 상태의 재진입을 검증했다. 트레이 직접 UI 자동화는 `NOT RUN`이다.
