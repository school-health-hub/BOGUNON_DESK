- 외부 owner는 기존 `P0App.financeOpen` 하나만 유지한다.
- 내부 데이터 owner는 기존 `FinanceScreen`과 Finance IPC/SQLCipher 계층이다. 새 전역 owner나 저장소를 만들지 않았다.
- 별도 로그인·인증 화면은 현재 구현에 없어 해당 검증은 N/A이다. 기존 Finance 가용성 확인과 fail-closed 차단 화면은 유지한다.

- SQLCipher/DPAPI, 암호화 파일 형식, IPC, 백업·복원, 저장 실패 후 stale 처리, 초안 및 메모리 수명주기는 변경하지 않았다.

## App Shell 통합

- 위치: `일정·업무 / MY FINANCE`
- UX-02 registry의 기존 Finance 정의와 `schedule-work` 카테고리를 재사용한다.
- Rail, 내부 `일정·업무로`, Home/다른 카테고리 이동은 동일한 외부 close-request 경로를 사용한다.
- dirty 초안이 있으면 기존 Finance 확인 모달을 사용한다. 취소 시 Finance Workspace, 초안, 활성 Rail이 유지되고, 확인 후에만 close/unmount한다.
- 기존 confirmation/backup modal 또는 쓰기 busy/locked 상태에서는 자동 재시도 없이 이동 요청을 거부한다.
- 암호화 엔진 가용성을 확인 중이거나 fail-closed unavailable 화면인 동안에도 App Shell 이동 요청을 요청 ID별 정확히 한 번 처리한다. 이 상태에는 초안이 없으므로 기존 close cleanup을 실행한 뒤 목적지 이동을 승인하며, 데이터 가용성·암호화 판정 자체는 완화하지 않는다.
- Home의 지속 마운트, TD2/Dock, 다른 업무 모듈 owner는 변경하지 않았다.
