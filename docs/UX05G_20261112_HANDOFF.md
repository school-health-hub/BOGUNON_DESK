## 실제 owner와 진입 구조

- Renderer의 단일 진입 owner는 기존 `P0App.workspaceOpen`입니다.
- `WorkspaceProductHost`는 기존 `window.electronWorkspace` 고정 API를 `ProductWorkspace`에 전달하며, 별도의 인증 또는 DB 세션 owner를 만들지 않습니다.
- SCHOOL을 닫으면 Renderer store가 unmount되고, 재진입하면 Main runtime의 현재 세션과 권한 상태를 다시 조회하는 기존 계약을 유지합니다. 닫기나 Rail 이동이 로그인·로그아웃 또는 권한 변경을 실행하지 않습니다.

## 학교 기능의 세 경계

1. `학교 연결`은 이 PC의 로컬 학교 프로필과 업무 주소 설정입니다.
2. `학교 행정`은 외부 공식 업무 사이트와 로컬 행정 도구입니다.
3. `학교 공동 공간`만 승인된 역할과 서버 권한을 사용하는 SCHOOL 공유 데이터 영역입니다.

로컬 학교 설정 완료는 SCHOOL 인증 완료로 취급하지 않으며, 세 영역의 owner와 저장소를 결합하지 않았습니다.

## App Shell 통합

- `학교 > 학교 공동 공간`에서 기존 typed registry와 `workspaceOpen` owner를 사용합니다.
- 기존 전역 대형 overlay를 제거하고 `AppShell.workspace`의 Main Workspace outlet에 기존 `WorkspaceBoundary > WorkspaceShell > WorkspaceProductHost`를 표시합니다.
- Rail 선택과 현재 위치는 `학교 / 학교 공동 공간`으로 표시합니다.
- 내부 `개인 업무 · 이 PC로 돌아가기`는 `학교` 카테고리 목록으로 복귀합니다.
- Home은 기존 App Shell 안에서 계속 마운트되며 SCHOOL과 겹쳐 보이지 않습니다.
- SCHOOL 내부 확인·MFA 모달의 포커스·Escape·배경 차단은 변경하지 않았습니다.

## 인증·권한·Trusted MFA 계약

- Main/Preload/IPC, 인증 프로토콜, PostgreSQL/RPC/SQL/schema, 역할 검사, 학교 간 격리 코드는 변경하지 않았습니다.
- 미인증·만료·연결 실패·권한 거부 시 공유 상태를 비우거나 잠그는 기존 동작을 유지합니다.
- Trusted MFA의 `mfaVerify`/`mfaCancel`과 purpose-bound 검증을 변경하지 않았습니다.
- Trusted MFA 포트 미구성 시 관리자 추가·이관 `CLOSED` 계약을 유지합니다.
- 이번 UI 통합은 운영 인증, 운영 PostgreSQL 또는 Trusted MFA 성공 검증을 포함하지 않습니다.
