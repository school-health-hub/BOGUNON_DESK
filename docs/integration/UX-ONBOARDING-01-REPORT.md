## 동작과 보존 계약

- 온보딩 완료 여부는 `poc-settings/onboarding.json`에 별도로 저장한다. 기존 `layout.json`, `desktop-surface.json`, 메모 및 업무 데이터 스키마는 변경하지 않는다.
- 기존 데이터가 있는 프로필은 온보딩을 표시하지 않는다. 신규 프로필만 안내하며, 완료 후 재실행 시 반복하지 않는다.
- 모드 선택은 기존 Desktop Surface 모드 저장 경로를 사용한다. 기본 Palette는 유지하고 사용자가 Workspace를 쉽게 찾도록 최초 안내를 Workspace 창에 표시한다.
- 계정 확인은 고정 종류와 일회성 ID를 가진 IPC로 전달한다. Main은 기존 sender 검사와 재확인 후에만 기존 인증 함수를 호출한다. 비밀번호·토큰·인증 코드는 렌더러로 전달하지 않는다.
- 연결을 거절하거나 확인창을 닫으면 기존 계정·학교·로컬 자료는 바뀌지 않는다.

## 검증

- Electron TypeScript 3개 설정 및 제품 빌드 **PASS**.
- 실제 Windows Electron 격리 GUI E2E **PASS**: 980×700 첫 실행·설정·계정 모달, ESC, 재실행, 기존 레이아웃 프로필의 온보딩 미표시와 원본 파일 보존.

- `git diff --check` **PASS**.

## 미검증과 후속

- 실제 Google 로그인·취소 콜백·세션 유지: **NOT RUN**. 사용자 계정 인증을 실행하지 않았으며 이 변경의 인증 계약은 기존 계정 서비스 테스트로만 확인했다.
- 현재 격리 빌드에는 공개 로그인 설정이 없어 실제 계정 연결 버튼이 비활성화된다. 계정 모달 GUI는 합성 이벤트로 확인했다.
- 1440×900 및 다양한 배율의 이 변경 화면은 **NOT RUN**. 980×700에서 온보딩·계정 모달의 버튼 접근과 가로 overflow 부재를 확인했다.
- Newsletter 디자인 편집기 등 고급 패널의 `revision`·JSON 형식 안내와 일부 `window.confirm`은 남아 있다. 데이터 보존·파일 교체 확인을 건드리지 않기 위해 별도 집중 UX 검토가 필요하다.
- 후속 설치 후보를 만들 때는 현재 커밋으로 다시 빌드하고 새 EXE 해시와 실제 인증 설정을 검증해야 한다. 이번 작업은 패키징·설치·배포를 수행하지 않았다.
