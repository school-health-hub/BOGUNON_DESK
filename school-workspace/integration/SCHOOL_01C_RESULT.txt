4. 인증 → RPC → 멤버십 연결
B 실제 AuthAdapter 클래스 → C 플랫폼 port → 공통 Coordinator → B DTO 검증 → C 로컬 SQL transport
→ A의 public ws_v1 RPC → ws_runtime/reader와 실제 RLS → 합성 학교 데이터의 흐름을 검증했다.
Auth 공급자·callback 발급·세션 저장용 cipher는 MOCK, DB·RLS·RPC는 LOCAL DB다.
JWT 서명을 검증한 hosted Auth 결과가 아니다. local registry에 등록된 정확한 토큰만 신뢰 게이트웨이로 취급한다.
일반 RPC는 school_client 로그인으로 authenticated 역할에 진입하며 postgres/service_role로 성공을 우회하지 않는다.
postgres 사용은 DDL, fixture, 검사와 명시적 상태 변경 주입에 한정한다.
7개 ws_v1 계약을 재사용한다. C에서 실제 DB로 bootstrap/get_context/set_member_role/set_membership_state를 실행했다.
request_join/decide_join/leave_school은 A 원본 및 B DTO 계약을 보존하며 C 신규 UI에서 새로 end-to-end 실행한 것으로 세지 않는다.

로그인 전/중/학교 미선택/pending/approved/정지/소속 만료/복구 잠금/세션 만료/네트워크 오류를 구분한다.
클라이언트 역할 표시와 서버 인가를 분리하며 매 명령 전 사용자 및 DB 멤버십·컨텍스트를 다시 확인한다.
학교 전환/계정 변경/로그아웃은 generation 변경과 abort로 이전 응답 및 메모리 컨텍스트를 무효화한다.
승인되지 않은 상태에는 공동 RPC를 허용하지 않으며 서버도 별도로 거부한다.
A get_context가 pending 등에서 공유 자료를 거부하는 동작은 유지했다. C 상태 RPC는 self-status만 보완한다.
이 RPC는 ws_c_membership_status라는 로컬 실험 이름이며 운영 도입·이름·DTO 승인이 완료된 migration이 아니다.
