기존 EDUCATION_OFFICES 및 validateSchoolQuery를 재사용한다. 실제 NEIS 네트워크 조회는 연결하지 않는다.

교육청/학교코드는 문자열이며 '0000001' 같은 선행0이 보존된다. 이름 수동 입력이나 개인 학교 프로필로 서버 공간을 활성화하지 않는다.

희망 역할은 보건교사/보건지원강사뿐이다. 최초 신청과 승인에서 SCHOOL_ADMIN을 선택할 수 없다.
교사·지원강사 가입 → pending → 관리자의 승인/반려 → 신청자 새로고침 → 실제 서버 상태와 권한 갱신을 구현했다.
중복 신청은 UI와 서버에서 차단한다. pending은 공동 컨텍스트에 접근하지 못한다.
신청 철회는 확인 후 처리하며 재신청 시 epoch를 새로 생성하고 이전 역할을 복원하지 않는다.
반려/철회/정지/회수/만료와 승인 완료를 구분한다. 지원강사 승인에는 미래 유효기간이 필요하다.

새 학교 개설은 unclaimed 합성 directory만 허용한다. 요청 후 pending 저장과 신청 현황까지 제공한다.
최초 관리자 자동 승인 및 운영자 승인 RPC는 없다. 실제 재직/위임 확인 완료라고 표시하지 않는다.
검증 담당자/절차가 미확정이므로 운영 최초 관리자 승인 버튼은 명시적으로 비활성이다.

5. 관리자·지원강사 권한 방어
승인된 현재 학교 관리자만 해당 학교 대기 신청·구성원 목록을 조회하고 승인한다.
신청자 표시는 학교별 멤버 코드·희망 역할·신청일이며 이메일/실명/연락처를 수집하지 않는다.
타 학교 목록·자기 승인·지원강사 관리자 API·지원강사 즉시 관리자 승격은 서버에서 거부한다.
명시적 self guard는 관리자 본인 신청을 주입한 합성 이상 fixture로도 검사했다.
역할 변경/정지/회수/유효기간 변경은 확인 후 version 검사 RPC를 거치며 최신 결과를 다시 조회한다.
마지막 관리자 탈퇴·강등·정지는 실제 서버에서 차단한다. A학교 복수 관리자 및 B학교 마지막 관리자 fixture를 사용했다.

관리자 추가/이관은 기존 A propose→accept를 사용한다. 제안만으로 대상 역할이 바뀌지 않는다.
현재 관리자의 최근 재인증 증거, 대상의 승인된 교사 자격, 대상 본인의 수락·최근 재인증, 학교/epoch/version을 확인한다.
이관 성공 시 대상 승격 후 기존 관리자를 교사로 바꾼다. 지원강사는 후보가 아니다.
재인증은 합성 session.created_at 갱신 fixture다. 실제 공급자 재인증·MFA·재직 확인이 아니며 운영 승격은 비활성이다.
일반 RPC는 school_client/authenticated로 실행한다. postgres는 로컬 DDL·fixture·catalog·명시적 실패/reauth 주입에만 사용한다.
ws_runtime/reader는 NOBYPASSRLS·비소유자이고 원시 테이블 접근 및 감사 수정은 거부된다.
