4. 생성·배정·상태 변경
관리자와 교사는 생성·편집·복수 배정·상태 변경·완료·취소·보관·이력을 사용할 수 있다.
등록은 내용과 배정을 한 번에 저장한다. 편집과 재배정은 별도 명시적 version 명령이다.
배정은 같은 학교의 현재 승인·유효·활성 account/membership만 받으며 실제 current epoch를 서버에서 기록한다.
지원강사는 현재 epoch의 본인 배정 업무만 TODO→IN_PROGRESS→DONE으로 변경할 수 있다.
건너뛰기·DONE 되돌리기·다른 사람 완료·본문/담당자/우선순위/기한 변경·생성/취소/보관/이력은 거부한다.
다른 학교 task ID와 없는 task ID는 공통 접근 거부다. 관리자 설치 여부는 권한 근거가 아니다.
보관은 soft archive이며 하드 삭제 RPC는 없다. 구성원 이탈 후에도 학교 기록과 작성 epoch가 남는다.

5. 권한 검증
서버는 매 요청에 account/session/학교 상태·현재 승인 멤버십·유효기간·역할을 재검사한다.
개별 task.read deny override도 현재 epoch 기준으로 반영한다. UI cache나 JWT의 사용자 편집 metadata는 인가 근거가 아니다.
정지·회수·만료·pending 계정은 새 요청을 거부한다. 재가입 epoch 변경 후 옛 배정으로 상태 변경하지 못한다.
RLS와 UPDATE trigger가 비관리자의 본문·불변 identity 변경과 허용되지 않은 상태 전이를 다시 막는다.
실제 변경자/시간/version은 서버에서 정한다. 임의 작성자/수정자/시각 인수를 RPC에 받지 않는다.
이력은 actor member_code·action·version·from/to 상태·시각을 담으며 과거 제목/본문 snapshot을 저장하지 않는다.
원시 테이블 SELECT/수정, 감사/이력 삭제 및 타 학교 담당자 배정을 부정 테스트했다.
