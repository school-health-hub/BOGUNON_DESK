# 향후 NSIS 격리 설치 QA

현재 NOT RUN: 설치, 업그레이드, 제거, 재설치, 재설치 후 데이터 복원. 이미 생성한 NSIS를 재빌드하지 않는다. 집 PC 기본 사용자에 시험 설치하지 않는다.

## 필요한 환경
이미 사용 가능한 독립 Windows VM/테스트 사용자 환경을 확보한다. 새 Windows 기능 활성화·관리자 권한 상승은 별도 승인 없이 하지 않는다. Windows Sandbox라는 이유만으로 일반 사용자 권한이라고 가정하지 말고 현재 프로세스 토큰을 확인한다. 호스트 사용자 AppData/레지스트리/시작 메뉴와 분리되는지 확인한다. 호스트 파일은 입력 EXE 읽기 전용 매핑과 전용 합성 출력만 허용한다.

## 자동화 순서
1. 위 검증 SHA와 installer PE asInvoker를 대조한다. 설치 전 해당 테스트 환경의 설치 등록·바로가기·프로필 baseline을 기록한다.
2. 일반 사용자로 설치 마법사를 실행한다. UAC 요구가 나타나면 진행하지 않는다. UIAutomation으로 installer PID와 자식 프로세스/창 소유 관계를 검사해 버튼을 조작한다.
3. 경로·제품명·버전·아이콘·시작 메뉴·바탕화면·프로그램 제거 등록을 확인한다. 호스트 환경 등록은 조작하지 않는다.
4. 설치본을 격리 프로필에서 실행하고 Playwright로 Dashboard/로그인 버튼 및 합성 메모 저장→정상 종료→재실행 보존을 검사한다. 계정 인증은 별도 승인 없이 하지 않는다.
5. 정확한 테스트 설치 경로와 제거 등록에 대응하는 공식 uninstaller만 실행한다. 데이터 삭제 옵션과 delete-app-data 인자를 사용하지 않는다. 제거 후 실행 파일/등록/바로가기 제거와 합성 사용자 데이터 해시 보존을 확인한다.
6. 동일 NSIS를 재설치해 합성 데이터를 읽고 hash/내용을 확인한다. 업그레이드는 별도로 검증된 이전/다음 버전 및 데이터 호환성 기준이 있을 때만 수행한다. 같은 버전 재설치를 업그레이드 PASS로 표시하지 않는다.
7. 각 단계 실제 GUI·등록·출력·SHA를 기록하고 실패 시 자동 재시도하지 않는다. 테스트 환경의 새 프로세스만 종료한다.

실제 설치 자동화는 아직 구현/실행 검증되지 않았다. 이 절차를 실행 결과나 설치 승인으로 해석하지 않는다.
