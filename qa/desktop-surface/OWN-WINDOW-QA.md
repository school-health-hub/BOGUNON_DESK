# 9B-2P: own-window QA implementation, NOT execution approval

The `desktop-surface-own-window` target requires `own-window-qa-skip-miri`, has
`test=false` and `bench=false`, and is not the existing Shell Live Runner.
Its default embedded source SHA is UNSET, deliberately rejected by its Gate.
Do not embed a clean commit SHA to misrepresent these uncommitted implementation
bytes. A later reviewed checkpoint needs a separate artifact build and approval.

This implementation creates at most one hidden, unowned top-level window in its
own process; the first scenario has no automatic retry/replacement. It exercises
the actual K lifecycle and L Router with synthetic Main state and records command
requests without executing them. Model/native identities remain separate.
Creation/destruction notifications preserve the original binding. The current
scenario uses synchronous creation/destruction callbacks; asynchronous user-input,
message-pump scheduling and replacement are not claimed tested.

## Verification permitted before approval

- Pure tests: `cargo test --offline --locked --manifest-path qa/desktop-surface/Cargo.toml --lib`.
- Synthetic subprocess: same manifest, `--features own-synthetic --test own_protocol_subprocess`.
- Native compile only: `cargo check --offline --locked --manifest-path qa/desktop-surface/Cargo.toml --features own-window-qa-skip-miri --bin desktop-surface-own-window`.
- Build may compile the gated target but must not invoke it, including with help,
  invalid arguments, via cargo run, or for a Gate smoke test.

Use an isolated QA CARGO_TARGET_DIR, not application/PR #14 targets. Do not run
the existing real-shell test. The synthetic fixture imports no native adapter.
Windows FFI is isolated behind the `-skip-miri` feature; compile/synthetic results
are not proof of real FFI safety. No nightly installation is required by this
step; unavailable Miri must be reported, not silently claimed PASS.

## New approval packet required before any actual run

1. Commit and independently review exact source and native call allowlist.
2. Build separately with process-local BOGUNON_OWN_WINDOW_SOURCE_SHA equal to
   that reviewed clean source. Verify actual executable SHA-256, PE architecture,
   profile/features and signature state. No existing manifest authorizes it.
3. Independently review a new four-field manifest: source_sha, executable_path,
   sha256, scope=`9B2O_OWN_WINDOWS_NO_SHELL`.
4. Independently review a new five-field descriptor: runtime_manifest_sha256,
   evidence_path, staging_path, run_claim_path,
   scope=`9B2O_OWN_WINDOW_EVIDENCE_V1`. Exact output basenames are
   own-evidence.json, own-evidence.staging.json, own-run.claim, in the descriptor's
   existing directory. No automatic directory creation or overwriting is allowed.
5. Record actual independent-review evidence and explicit operator execution
   approval separately. Runtime schema cannot authenticate a human reviewer or
   prove that manual approval happened; opt-in/hash checks are not that evidence.
6. The reviewer must approve an isolated, non-synchronized QA packet directory,
   outside application AppData, repositories, existing approval packets and user
   data. This policy is a review requirement, not inferred from a path spelling.
7. Recheck hashes, source and root-to-leaf reparse status. The process holds files
   and ancestor directory handles against ordinary modification/rename. Same-user
   malicious replacement and image-memory integrity are not fully prevented.
8. Confirm resource headroom, non-elevated Medium integrity, interactive visible
   station and the input desktop. Gate requires accessible input-receiving Default
   desktop; it never switches desktop or changes permissions.
9. Only after separate explicit execution approval may process-local
   BOGUNON_OWN_WINDOW_QA_OPT_IN=APPROVED_9B2O,
   BOGUNON_OWN_WINDOW_QA_MANIFEST and
   BOGUNON_OWN_WINDOW_QA_EVIDENCE_APPROVAL be supplied. No values are set here.

The exclusive persistent own-run.claim is created after preflight and before
class registration, denying a second attempt. Never delete/reset it to retry.
The enforcement assumes the approved files and claim are not maliciously removed.
No identity, approval file or descriptor is automatically generated by the runner.

## Output / Evidence / failure

CAPABILITY is always NOT_OBSERVED: no Shell capability is measured. WINDOW=PASS
requires lifecycle/Router/Main checks, zero remaining own windows, successful
cleanup and successful Evidence publication. Only fixed E_* and FAIL_CLEANUP may
follow the two status lines; stderr is empty. Cleanup, including owner release,
precedes Evidence. Counts absent due to early failure remain unknown.

Exit codes: 0 PASS; 2 Gate BLOCKED; 3 observation/model failure; 4 caught panic;
5 cleanup failure; 6 Evidence/output failure. Cleanup outranks panic, which
outranks ordinary observation/storage failures. A broken stdout writer returns 6;
no complete output is promised on a broken output channel.

Own-window Evidence schema v1 is separate from Shell Evidence v2. Its fields are
schema_version, runner_kind, capability, source_sha, artifact_sha256, counters,
remaining_own_windows, cleanup, reason and panicked. Unknown fields, invalid
version/enums and absent nullable fields reject. No HWND, PID/TID, paths, titles,
raw Windows errors or fixture payload are serialized. Publication uses create-new
staging, same-handle byte verification, sync and a non-replacing hard link; staging
is retained. Existing output/staging/claim rejects and requires a fresh separately
approved packet, not an automatic retry.

Only own class/window creation and destruction are allowed mutations. No
SetParent, style/z-order setter, ShowWindow, foreground activation, Shell lookup,
Explorer messages, hooks, elevation, foreign process termination, Tauri, WebView2,
AppData, IPC or financial storage is connected. Cleanup identity uncertainty
fails closed rather than destroying an unverified or retired handle.

Caught Rust unwinds attempt cleanup. Abort, OOM, forced termination, fatal FFI
errors and pre-hook failures cannot guarantee cleanup/evidence/output sanitation.
HWND ABA is reduced by captured tokens/tombstones, not proven impossible. No
actual Windows lifecycle, DPI behavior or cleanup has been tested in this phase.
