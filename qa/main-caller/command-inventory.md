# Registered custom-command inventory

Scope: the 48 entries in `src-tauri/src/lib.rs::generate_handler!`, baseline `20f165aa`, audited 2026-10-18. Implementation anchors are file + command symbol (line numbers move during this change). Frontend anchors identify the concrete invoke boundary, including wrappers with dynamic command names. No application, dialogs, credentials, user data, external browser, Windows API, or Explorer operation was executed for this audit.

**Required policy for every row: Main-only now.** This means a Tauri-injected Webview whose webview AND owning window match the setup-pinned Main identities; a label string, URL, JS argument, or existence of a `main` window alone is insufficient. Reject before invoking the operation closure or constructing/polling its async future, file/store/credential access, network clients, dialogs, state changes or shell calls. No custom command is approved for Surface. Native tray/startup callbacks remain separate trusted Rust paths, not invoke callers.

Columns: R = read; W = persistent/in-memory write; X = external effect. C/F/N explicitly name credential, filesystem, network access (`—` means no direct access found). `Prior guard` is baseline caller-identity guard, not input validation or mutex. All 10 prior guards are in auth/ChatGPT; the other 38 require the same wrapper. Classification includes transitive helpers. Existing sensitive return shapes are **not** Surface projections.

## Potential future projections — no current permission

A separately reviewed backend projection might expose a bounded meal/weather display, safe counts or launcher availability flags; it must omit bearer tokens, raw session/account identity, portal/account URLs, full paths, extracted documents, purchase raw rows and diagnostics. Such a projection needs its own minimal DTO, explicit registered Surface identity and generation, source freshness/revision, destination-specific delivery, revocation, size bounds and tests. Do not relabel any existing command as `SurfaceAllowed`; even read-looking getters can touch credentials, network, stores, migration or OS metadata. Main-only does not imply the returned data is safe to broadcast.

## Coverage and evidence method

Read actual registered wrappers and transitive helpers in `auth.rs`, `chatgpt/{commands,lifecycle,storage,plan}.rs`, `ai*.rs`, `launcher.rs`, `browser_launcher.rs`, `notifications.rs`, `work_folders.rs`, `purchase_helper.rs`, `purchase_settlement.rs`, import modules, `meal.rs`, `weather.rs`, `desktop_surface/{mod,probe}.rs`, plus frontend service/invoke/event sites. Command names were reconciled against the single 48-entry handler registration. Plugin commands (store, dialog, opener, deep-link, updater, notifications, autostart) are a separate capability boundary, not part of this 48-command count. JavaScript wrappers, runtime checks and input schemas do not establish native caller authority. See `event-boundary-audit.md` for event/internal paths that do not pass through these wrappers.
