# Purchase Phase 2B1 UI Windows verification

Focused UI controller for the approved product checkpoint. The new workflow uses literal `db6acfe7fbbb9a249defe9fcb9542b5330192425` pins, an independently checked-out controller SHA, current feature-branch/workflow context gates, and a controller delta restricted to this folder and `.github/workflows/purchase-phase2b1-ui-windows.yml`. The old Phase 2A/2B1 QA files and workflows remain unchanged. Only the new UI workflow and QA paths trigger this run.

The GitHub-hosted Windows 2022 runner copies the product checkpoint's tracked `qa/purchase-phase2b1` harness into an untracked `qa/purchase-phase2b1-ui` directory and overlays these controller files. This preserves the baseline fixtures, real panel/hook/reducer/styles/fonts, security routes, native-denial adapters, keyboard and preview tests. Baseline `package.json` and `package-lock.json` are reused byte-for-byte and explicitly hash-checked after overlay. Playwright 1.56.1 and Node types 22.18.6 use the existing QA lock; no dependencies are added. All original tracked product files, including old QA files, are hashed before and after execution.

Node 22.23.3 and action revisions are pinned. Product and QA dependencies use separate `npm ci --ignore-scripts` installations on the hosted runner. Validation includes product TypeScript, six focused suites (preview hook, preview model, clipboard, settlement, dialog, settlement editor), standard `npm run build`, QA TypeScript, test listing, and headed Chromium. Playwright runs only `preview.spec.ts`, `keyboard-layout.spec.ts`, and `korean-preview.spec.ts`; bulk tests are not repeated. The seven new scenarios cover all four Korean tax labels while preserving selector values, tax amount, item state and legacy settlement numbers/table shape; dialog visible text rejects raw mode codes. At 1440×900, 1024×768 and 980×700, actual guidance DOM ranges verify that Korean words which fit a column stay on one line, computed guidance styles require `word-break: keep-all` and `overflow-wrap: anywhere`, and long table names, scrolling, captions, output button access and Escape focus restoration are checked.

Full Vitest and Rust tests/check are **NOT RUN** for this UI-only change; the previous successful baseline remains separate evidence, and Rust source/dependencies are unchanged. No NASM or Rust setup is performed. Native Tauri/WebView2 IPC, native preview/save dialogs, actual OS clipboard output, real database/auth, IME composition, Windows DPI and receiving-PC restoration are **NOT RUN**. Viewport sizes do not emulate display DPI. Tests inspect output availability without writing to the OS clipboard. Native repositories reject excluded operations; no synthetic IPC response is used to claim native coverage.

Each stage is PASS, FAIL or NOT RUN in the manifest. Failure stops later stages; skipped checks never become PASS. The runner detects leftover QA listeners and checks product HEAD/bytes after execution. Always-uploaded 14-day evidence includes isolated stage stdout/stderr, focused Vitest JUnit, browser JSON/JUnit/HTML reports, screenshots, failure traces, diagnostics, browser/runtime versions, controller delta, product hashes, workflow outcomes and a complete SHA-256 inventory including hidden files. No local installation, build, browser or Rust execution is authorized or needed to author this controller.
